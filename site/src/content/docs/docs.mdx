> **Pre-alpha:** Checkride validates drill specifications, evaluates recorded DrillRun evidence and runs one disposable PostgreSQL restore across two k3d clusters. It does not establish evidence provenance, run production restores or certify recovery.

Checkride is an open-source project for testing recovery of Kubernetes applications, including their data. Explore the [product overview](/), [system design](/product/) and [evidence model](/evidence/) before using the [local walkthrough](/start/).

## Start a local session

In one terminal, start the Go validation API:

```bash
go run ./cmd/checkride-api
```

In another, start the interactive Studio:

```bash
cd studio
npm ci
npm run dev
```

Open `http://127.0.0.1:5173`. Import or edit a JSON drill, run validation, inspect errors or warnings, and download the edited file. The Studio sends the document only to the local API. It does not connect to a cluster.

The acknowledged-write ledger can compute exact RPO from test data today. The separate k3d runner captures V0–V3 evidence from a locally executed restore. General-purpose orchestration, trusted evidence provenance and V4 application checks remain planned. The [source repository](https://github.com/jagarkarlo/checkride) is currently private; access to source links requires permission.

The Go evaluator builds RTO/RPO reports from captured DrillRun JSON, exposed by the local API and `checkride-report` command. The [roadmap](/roadmap/) separates the narrow lab runner from planned general-purpose restore orchestration.
